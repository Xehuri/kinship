## 0. 一句话目标

替换 axeuh-health-monitor/ai 的 opencode serve（127.0.0.1:5096），用自研 TypeScript
harness 实现：上下文工程（缓存命中+协作契约）、工作流治理（触发→副会话→兜底→审计
闭环）、长期扩展（沙箱接缝、热自定义），只服务本项目，不追求兼容 opencode 接口。

  现有文件。开发与测试一律另开端口（默认 5097 起）+ 另建目录。
- 工程产物全部放新目录：`server/axeuh-harness/`。
- 切换（launcher 换 binary、后端重写接线）是未来单独授权动作，本计划只到"影子验证
  通过、切换方案就绪"为止。
- 环境事实（2026-10-07 实测）：node v20.20.2 / npm 10.8.2 可用；**bun 未安装**；
  python3 3.12（系统）+ /opt/venvs 存在；git 可用；WSL2 挂 NTFS（inotify 跨系不可靠，

## 2. 架构与范围

- **D1 解耦化**：不做 opencode 兼容层；自有 HTTP+事件协议；后端 client 层重写换。
  长期规划优先于最快跑通。
- **D2 丢弃 opencode.db 契约**：不兼容其 SQLite 内部 schema；ai/analysis 三个直读
  脚本（session_context.py / query_session_stats.py / audit_collector.py）改为读
  harness 的 state 文件（jsonl journal + transcript 导出），不为其开查询端点。
- **D3 语言**：TypeScript（node20 运行时；是否装 bun 由复用底座评估定）。
- **D4 单工作区**：只服务 axeuh-health-monitor 一个项目；无 x-opencode-directory 式
  多目录机制；工作区指针写在部署配置。

## 3. 会话模型（三实体）

- **D5/D22 主会话（Session）**：唯一与用户交互的长生命周期体（网页/语音/回执都进它）。
  与副会话"靠产物协作不靠对话协作"：禁止活信道（steering 副会话、中途喂话、结果回灌）；
  允许产物快照（文件/git/账本/transcript 单向读）。
- **D5 子智能体（保留，主会话派发）**：结果回灌主会话上下文，服务即席合成
  （"结果进对话→子智能体；结果进文件系统→副会话"）。定义=提示词文件+模型路由。
  内置类型自造：general（通用）+ explore（探索）起步（D24）。
- **D19 副会话（Run，流水线工作流）**：每次开干=全新会话，无残留；终态盖棺。
  由触发器/排班/手动 dispatch 驱动，不依赖主会话派发（主可 dispatch 但非必须）。
- **D25/D30 终止机制（收束）**：弃用"无工具调用即停"，改为**收束工具成功调用
  （必填字段齐）才停**。正文与收束调用同一条模型回复内完成，零额外往返；
  收束可与干活工具同轮；字段不齐=催办。收束参数=回执 schema（主会话：三态
  已完成/待用户回应/需用户确认；副会话：批次回执）。收束后本轮盖棺，下条消息开新轮。
- **D26 上限（全部热载可改）**：空转催办 5 次；同工具同错 3 次升级提示；
  单请求轮数硬顶按工作流配（如 60）；跨请求自动续跑 2 次。超限分级处置：
  副会话→failed 进死信投主+通知；主会话→自动收束"需用户确认"如实说明卡点，
  绝不静默假完成。
- **D23 协作主干**：副会话终态回执**默认直投主会话**（收件箱消息，带
  【副会话回执】前缀），主=调度与验收枢纽。回执 schema：run_id/工作流/状态/第几次
  尝试 + verification 预验块（harness 代跑：产物清单存在性、commit body 字段齐全、
  check_coverage 类校验）+ digest 一行结论 + dispositions 待处置清单 + pointers。
  主默认只读 digest，异常才深挖。
- **D23③ 通知双轨保留**：副会话可直发用户通知（现状 ai-mcp 通道）；主会话收平行
  回执做处置。inbox/notify 降级为逐工作流可选档（低频/噪声源用）。
- **D22 防环与写权**：副会话禁止派生副会话；副内可用子智能体工具（委托型业务）。
  工作流声明可写路径集，越界写=拒+审计事件（v1 软警告，沙箱期强制）。
- **D21 needs_decision 例外环**：副会话遇歧义→终态 partial+异常清单→主判断→
  带 resolution 重派同族 run（fresh 会话）。不发明实时问答信道。

## 4. 任务系统（整体归 harness）

- **D14 归属定形**：排班 cron、挂载脚本、账本、队列、兜底、审计、（可选）transcript
  导出同住 harness 一体内。backend TaskScheduler/script_runner 退役删除；
  任务管理页 API 由 backend 转薄代理。
- **D15 兜底=期望账本**：expected（开火即落盘，先于执行）/ actual（终态）差集=缺口。
  对账器常驻低频扫描，无内存态，重启全量重放 L0。catchup 策略逐工作流声明：
  latest（补最近一班，数据检查型）/ all（计费型）/ none（提醒型作废）。
  重试两级（D19）：自动续跑=同 run 同会话 resume；catchup 补跑/人工重跑=新会话，
  账本记 attempt/trigger/parent_run。dead-letter→回执投主。
- **D24 触发形态（六刀后）**：v1 只有两种——cron 排班 + 挂载脚本的 dispatch 事件。
  声明式事实规则 DSL 推迟（脚本宿主已覆盖自定义规则需求）。cooldown/去重放 dispatch
  准入层参数（dedup_key + max_inflight），不做租约池。
- **D31（新增默认案已圈）排班暂停开关**：全局+逐工作流布尔，账本准入层实现。
- **D17/D18 挂载脚本**：语言中立子进程（永不 in-process）。协议=frontmatter
  {enabled,...} + stdout JSON 行事件：fact / deliver / dispatch / heartbeat(可选报活)
  / reserved:exec。默认 Python（存量脚本平移），TS 自愿（同一协议）。崩溃 respawn+
  指数退避（launcher ensure_opencode 范式）。脚本住 ai/scripts/，热加载。
- **D16 数据面边界**：backend 继续只管"接收/存储/投递"；新数据源=backend 加采集器
  进程+落盘 ai/data/（README 声明 schema），harness 零改动。跨界 API 仅投递类。
  文件监听=轮询 mtime+size 水位线（NTFS/WSL2 现实）。

## 5. 上下文与记忆

- **D6 缓存优化对象**：memory 目录注入的 prompt 缓存命中 + 每工作流执行提示词的
  前缀稳定。
- **D21 装配纪律**：稳定前缀层（AGENTS.md/SELF-INDEX/工作流提示词，字节级恒定，
  变更走尾部）→ boundary 摘要块 → 增量易变层（回执 digest 等，尾部注入）→ 本轮消息。
  同工作流跨批次共享 warm cache（参数块恒在尾部）。
- **D21 压缩定形**：compaction=harness 内部例程（单次非流式小模型调用，摘要模板热载
  于 ai/config/），非 agent 非副会话；无工具无记忆写权限。触发=水位 85% 兜底 +
  复盘收口锚点错峰；不做声明式时机调度（三.3 砍）。产物=boundary 事件+摘要块进 L0，
  溢出原文留档，快照带指针可回读（read 按需读回，不自动塞回）。分级微压缩先行：
  单工具输出超阈值即截断落文件留指针。主会话全闭环；子智能体轻量水位兜底；
  副会话 run 默认不压缩。每次压缩落执行轨迹（前后 token/耗时/缓存断点）。
> **2026-10-21 实现注**：生产 worker 路径（声明 `compaction.fallbackTokens`）为 `summaryMode: auto` + compact-6 模板 + 投影摘要 + `coveredCount`/`tailIncluded` boundary；D21 的“单次非流式小模型”仍描述 legacy auto hook（未声明 `fallbackTokens` 时）。详见 docs/06 §5.4.1。
> **2026-10-22 实现注**：worker 默认双视角摘要（ops + chat，合成一条 `summaryText`、单 boundary），`compaction.summaryPerspectives: ["ops"]` 可回退单 ops 摘要；legacy 路径仍单份 9 段摘要。
- **D21 复盘一等接口**：主会话 transcript 原样 jsonl 增量导出到 ai/data/sessions/
  （贴 boundary+每日收口双触发），供复盘副会话"读主上下文做混合分析"（D5 的合法
  产物快照通道，不是活信道）。
- **D16/理念继承**：记忆体系本身（fact/profile/self、单一真源、写入治理）原样保留
  文件约定；harness 只接管"怎么注入"，不重新发明"怎么存"。注入编排在
  ai/config/injection.yaml 声明（分层清单/全量|增量|按需/cache 布局），热加载。

## 6. 配置与热加载

- **D28 三文件三分层**：
  1. backend config.yaml（现状，删 opencode 段换 harness 端点指针）——后端部署级，不热载；

  版本控制内）。热加载对象=声明式+提示词模板；代码级热插拔留给沙箱期（D7）。

## 7. 沙箱（后期，v1 只留接缝）

- **D7 接缝**：一切副作用走 ToolExecutor 单缝 exec(cmd, cwd, env, timeout, paths)；
  工具不得自己摸 child_process。缝上声明 SandboxProfile{fs/net/cmd_allow/deny/rlimit}
  ；v1 实现=chdir+路径断言（ai/ 边界纪律强制化）；沙箱期换 bubblewrap/容器，上层零改动。
  permission-gate（审批门）共用同缝。挂载脚本子进程边界天然是第二处接缝。
- 立场：沙箱 harness 永不托管数据处理脚本主体（感知判定留脚本子进程即可，隔离级别
  到"路径断言+rlimit"够用）；收严对象=agent 工具与将来代码级热载。

## 8. 可审计

- **trace 语义**：一次执行=一条 trace，阶段骨架：
  queued→admitted(准入：去重/并发/暂停判定)→assembly(装配规模)→turn[i]→tool[j]→
  summary(收束/回执)→delivered。每 span 记：起止耗时/token in-out/缓存读命中/
  模型供应商/失败与重试原因/催办事件。工具级粒度（v1 即含，堵塞点审计原始需求）。
- 存储：ai/state/trace/{date}.jsonl 分片。查询端点做明细；聚合统计 v1 不做端点
  （analysis 脚本从 jsonl 算，投影层推迟同一逻辑）。
- 配置改动与执行后果同轴可查（config.applied 事件带前后版本 hash）。

## 9. 存储

- **三层**：L0 ai/state/ jsonl append-only 唯一真源（session/{id}.jsonl 分片、
  ledger/{date}.jsonl、trace/{date}.jsonl、config/{date}.jsonl）；L1 SQLite 投影
  **推迟到疼了再建**（会话历史分页走文件游标，语义沿用 x-next-cursor）；
  L2 ai/data/ 业务文件层不变。
- **D20 性能纪律**（针对"超长会话变慢"）：装配恒 O(增量)只读 boundary 后；L0 按
  N 轮分片+目录索引；大工具输出 spill；读路径永不重放 L0 全量；trace 记装配行数
  验证恒定性。
- 崩溃即重放：expected 先落盘、进程重启全量重扫、无内存态。

4. 配置域：只读——清单+生效版本/校验回显/生效拒载日志。写=直接改 ai/config/ 文件
   （热加载是本体，不开写 API）。
5. 目录与健康域：模型列表(供模型设置页)/health/令牌校验。

不开口：prompt_async 兼容、/global/event 形状、旧 run CLI、share/TUI/LSP/snapshot。

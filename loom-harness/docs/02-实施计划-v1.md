## Decision: HTTP framework (settled in T26)

| Option | New external runtime dep | Pros | Cons | Verdict |
|---|---|---|---|---|
| A. raw `node:http` + hand-rolled router + SSE writer | none | Honors "pi-ai only runtime dep"; full control of SSE framing; tiny surface (~15 endpoints / 5 domains) | manual body parse, routing, 404/405; ~150 LOC plumbing | **RECOMMENDED (default)** |
| B. express / fastify | yes (violates frozen "only pi-ai runtime dep") | less boilerplate, middleware | dependency tree, weakens the frozen invariant, no real need | reject |
| C. vendor a tiny MIT router (copy ~200 LOC) | none | slightly less plumbing than A | extra vendored code to own; marginal benefit | acceptable fallback |

**Default = A.** T26 records the rationale in `docs` and builds a minimal router + SSE helper; the frozen `pi-ai`-only invariant is preserved.

## Feature scope v1 (must cover ALL frozen decisions)

- **D5/D19/D22/D23 main session** long loop with abort/steer/resume + tail repair; subagent `task` tool (in-process, results回灌 main); side-session runs = fresh session per run, ledger expected/actual, catchup latest/all/none, two-level retry, dead-letter → deliver to main.
- **D25/D26/D30/D31 convergence termination**: only a *successful 收束 tool call with complete schema fields* ends a turn; nudge limits 5 (idle) / 3 (same-tool-same-error) / 60 turn hard cap (all hot-configurable); scheduler-pause switches.
- **D23 receipt schema** with harness-side `verification` block (manifest existence + commit-body schema check).
- **D14/D15/D16/D17/D18 task system**: cron schedule files + mounted-script subprocess protocol (frontmatter + stdout JSON events `fact|deliver|dispatch|heartbeat`, reserved `exec`; python default, respawn + backoff); expected ledger; polling (mtime+size) only.
- **D6/D20/D21 context**: layered injection declared in `ai/config/injection.yaml` (stable byte-prefix ordering, cache-layout rules, digest tail-append, tool-output spill, per-N-turn journal sharding, O(increment) assembly); compaction internal routine (single cheap-model call, hot-loaded template, watermark 85% + daily-review anchor, boundary+summary block+pointer reread, microcompaction first); transcript increment export.
- **D10/D28 config plane** hot-reload four-piece contract (validate / atomic-swap / audit-trail / git rollback) for `ai/config/{injection,triggers,workflows,models}`.
- **D11/D8 trace/span audit**: queued→admitted→assembly→turn→tool→summary→delivered spans with tokens/cacheRead/model, tool-level granularity, JSONL to `state/trace/{date}.jsonl`.
- **D29/§10 five-domain HTTP API + SSE** with envelope `{payload:{type,properties}}`; sessionID on every event; idle needs id; `children[].id`; no-dash ids; `x-next-cursor` pagination; `local_sessions` nonempty semantics for compat endpoints; token usage fields.
- **D24 MCP stdio client** wiring loom-local ai-mcp equivalent (`send_notification` + `tts_speak`); **skills loader** (dir-based, per-session allowlist).
- **D7 ToolExecutor single seam** with declared `SandboxProfile` + naive enforcement (path assertion within workspace) + permission model allow/ask(default deny for destructive)/deny with agent+workflow scoping.
- **D27/D28 credentials**: `loom.yaml` with env-var references; actual keys from systemd/env; credential migration checklist = future-authorized.
- **D33** health endpoint; launcher-compatible serve CLI (`loom serve --port N --hostname 127.0.0.1`, TCP-ready <15s, SIGTERM graceful); SSE fan-out native to loom; exit interface stub; injection-source-missing = skip + audit (fail-soft); workspace = one config path (no hardcoding); **D34** naming.

**Explicitly out of scope:** opencode compat layer, rule DSL, SQLite projection, compaction scheduling, lease pool, heartbeat mandate, transcript md render, sandbox implementation, old-session migration, multi-workspace, bun, Effect, global config dir, TUI.

## Commit Strategy

- **Repo:** git init is **out of scope** (user decides). All tasks assume a repo will exist; if absent, commits are deferred until the user creates it. No task runs `git init` or config changes.
- **Atomicity:** one task = one commit; commit only when that task's VERIFY passes. Order = wave order.
- **Message style:** Conventional Commits with scope, e.g. `feat(loom-core): vendor agent kernel from harness-pi 0.5.0`, `feat(loom-server): sse envelope conformance (D29)`, `test(loom): compaction boundary (D21)`, `docs(loom): switch-day appendix (§11)`.
- **Never commit:** `config/loom.yaml`, `state/`, `fixture-workspace/` heavy dirs, `node_modules`, any secret literal. `.gitignore` is established in T01 before any other commit.
- **TDD discipline:** each feature commit includes its failing-first test made green; verification tasks (T39/T40) commit only docs/evidence.
- **Rollback:** code rollback via git branch/stash or file-level `cp` backup (project rule §5); config rollback via git under `ai/`.

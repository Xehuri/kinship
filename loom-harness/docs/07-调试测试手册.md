# 第一部 · 认识 Loom

## 1. Loom 是什么

Loom（织机）是 axeuh 自研的 agent harness，目标是替换现网 `opencode serve`（127.0.0.1:5096）。
命名分工（D34）：Loom 是织机，即躯体与 infra；"小贺同学"是织工，即 persona。隐喻对位职能：
经线=稳定前缀上下文，纬线=每轮增量，梭=排班穿梭。

- 工程位置：`server/axeuh-health-monitor/loom-harness/`；包命名空间 `@axeuh/loom-{core,server,tools,adapters}`；
  CLI 命令面 `loom serve [--port N] [--hostname H] [--config PATH]`（`loom runs/trace/doctor` 为
  命名蓝图 **[未来]**，等价能力走 HTTP API 与直读 state 文件，docs/06 §2）。
- 服务对象：只服务 axeuh-health-monitor 一个项目（D4 单工作区，无多目录机制）；
  不追求兼容 opencode 接口（D1，自有 HTTP+事件协议，后端 client 层重写换）。
- 进程内五能力（一图流全文见 docs/06 §1）：主会话（聊天，长生命周期，收束终止）、
  副会话引擎（定时/手动任务，每次 fresh）、子智能体（task 工具派发，上限受控）、
  上下文装配器（AGENTS.md+memory 注入，缓存友好）、L0 账本（`state/*.jsonl`）。
- API 五域（docs/01 §10，实际路由面 docs/06 §5）：会话域、任务域、事件域（SSE）、
  配置域（只读，写=直接改 `ai/config/` 文件）、目录与健康域。
  全路径需 `LOOM_TOKEN`（`Authorization: Bearer` 或 `X-Loom-Token` 头），无未鉴权路径，
  health 同样要 token（决策理由留档 docs/05）。
- 部署形态：systemd 单元 `axeuh-loom`（Restart=always），生产影子实例监听 127.0.0.1:5100；
  全库 MIN_PORT=5097，5096/8768/8769/18888 为现网禁碰口（D32）。
- 当前阶段：影子验证已通过（docs/03），切换须单独授权、清单就绪未执行（docs/04），
  即处于双通道观察期前阶段（ai_backend 开关未切）。真 provider 接线已收口（T39 完成，
  生产 5100 真模型运行，`smoke-real-model.sh` 全链 PASS；现行程序见 docs/04"修正"节）。

## 2. 为什么做：五痛点 → 五设计（对仗口径）

这是决策冻结时定形的对照（docs/01），逐条对位，不另编：

| # | opencode 之痛 | loom 之解 | 决策锚 |
|---|---|---|---|
| 1 | 上下文注入黑盒、缓存命中差 | 装配前缀字节恒定 | D6/D21 |
| 2 | 任务会静默消失 | L0 账本先记账 + 死信阶梯 + 对账 catchup | D15 |
| 3 | "假完成"无从分辨 | 收束工具强制终态校验 | D25/D30 |
| 4 | 受制于他人仓库 | 自有代码 + jsonl 状态真源 + 热重载四件套 | D1/D2/D10 |
| 5 | Node+Python 双栈割裂 | 单进程全家桶同址，一路 HTTP | D14 |

**痛点一：上下文注入黑盒、缓存命中差。**
- opencode 侧：记忆怎么注入、何时注入、前缀长什么样都不可知，prompt cache 命中听天由命。
- loom 侧：装配显式分层——段0 system（含收束工具说明）→ 段1 稳定记忆（AGENTS.md +
  `memory/**/*.md` 按路径字典序扫描，加文件即上线）→ 段2 任务提示词 → 段3 每轮增量。
  稳定前缀字节恒定、变更一律走尾部；契约测试钉死"同输入双跑 → 前缀段字节全等、
  prefixHash 全等"（docs/03 D6 行）。
- 缓存护甲：记忆文件含"日期+时分"级易变内容即判 invalid 降级占位，防打穿 warm cache（docs/06 §4）。

**痛点二：任务会静默消失。**
- opencode 侧：到点开火与漏跑都无凭据，消失了没人接得住。
- loom 侧：账本三件套。L0 先记账——expected 行在任何执行动作前落盘（`state/ledger/{date}.jsonl`），
  expected/actual 差集即缺口；死信阶梯——自动续跑=同会话 resume，catchup/重跑=新会话
  （记 attempt/trigger/parent_run），重试超限死信投主会话+通知，绝不静默；
  对账 catchup——重启全量重放、无内存态，补跑策略逐工作流声明（latest/all/none）。

**痛点三："假完成"无从分辨。**
- opencode 侧："无工具调用即停"，说完了和干完了无从区分。
- loom 侧：弃用该终止条件，收束工具（convergence）强制终态校验——只有收束调用成功且
  必填字段齐才盖棺，纯文本结束不停轮；字段不齐=催办（默认 5 次），超限主会话自动收束为
  "需用户确认"如实说明卡点。副会话终态再过回执预验：声明产物存在性、commit body 字段
  齐全、check_coverage 类校验由 harness 代跑（D23/D25/D30/D26）。

**痛点四：受制于他人仓库。**
- opencode 侧：harness 是别人的代码库，需求得向上游提，修复节奏不由己，
  opencode.db 的 SQLite 内部 schema 还被当成了隐性契约。
- loom 侧：三个真源交回自己手里——自有 TypeScript 代码库、自有协议、零兼容层（D1/D3）；
  状态真源=append-only jsonl（弃 opencode.db，D2），文件即真源，人与脚本皆可回放；
  行为配置热重载四件套（D10）：加载即校验、坏配置拒载留旧原子不换、`config.applied`
  留痕（前后 hash，查 `GET /config/audit`）、回滚=git 还原文件。

**痛点五：Node+Python 双栈割裂。**
- 现状侧：agent 在 Node（opencode serve），排班与脚本宿主在 Python（backend 的
  TaskScheduler/script_runner），任务语义横跨两套进程栈各说各话。
- loom 侧：单进程全家桶同址（D14）——排班 cron、挂载脚本、账本、队列、兜底、审计、
  transcript 导出同住 harness 一体内；serve/session/task/events/ops 一路 HTTP 走到底；
  切换日 backend 三个任务组件退役删除（docs/01 §11）。

## 3. 特点清单（速查）

- 收束才停：催办 5 / 同工具同错 3 升级 / 单请求轮数硬顶 60 / 跨请求自动续跑 2，全部热载可改（D26）。
- 前缀稳定：经线恒定、纬线进尾；压缩走 worker `summaryMode:auto`（预算内单次、超预算递归 depth≤2，boundary 写 `coveredCount`/`tailIncluded`，已覆盖前缀不重压）；worker 2026-10-22 起默认 ops+chat 双视角，合成一个 `summaryText`（`## OPS STATE` / `## CHAT STATE` 标记），`summaryPerspectives: ["ops"]` 回退单 ops 摘要；legacy hook（无 `fallbackTokens`）仍为 micro→full 两级、单份 9 段摘要（D21）。
- 账本化任务：expected 先于执行；retry 链可溯（attempt/trigger/parent_run）；rerun=新会话 attempt+1。
- jsonl 唯一真源：`state/` 下 trace/ledger/session/config/inbox/dead-letter 六类，append-only，
  内存不是真源，崩溃即重放（D2/D15/D20）。
- 热加载：`ai/config/` 改文件即生效不重启；坏配置拒载、旧配置继续服务，绝不崩（D10）。
- 全路径鉴权：token 只经请求头；sha256 摘要 + timingSafeEqual 定长比较防时序侧信道（docs/05）。
- 前端硬契约：SSE 只有 `data:` 行（绝无 `event:` 行）、信封 `{seq,payload:{type,properties}}`、
  `session.idle` 必带 sessionID、id 一律无连字符、`Last-Event-ID` 重连先补发后切 live（docs/06 §5）。
- 回执主干：副会话终态回执默认直投主会话（【副会话回执】前缀 + verification 预验块 +
  digest + 待处置清单），主默认只读 digest，异常才深挖（D23）。
- 双通道运维：后端 `config.yaml` `ai_backend` 双向拨（loom/opencode），回退=改配置重启、秒级；
  loom 的 state 数据保留不清，切来切去不串台（docs/06 §9）。
- 子智能体：内置 general/explore；并发（水平）与嵌套（垂直）上限热载；父取消自动传播子；
  结果回灌主会话并带 `task_metadata` 父子关系块（D5/D24，docs/06 §7）。
- 可审计观测：一次执行=一条 trace，span 记起止耗时/token in-out/缓存读命中/供应商/
  催办事件/失败与重试原因；配置改动与执行后果同轴可查（docs/01 §8）。
- 沙箱接缝：一切副作用走 ToolExecutor 单缝，工具不得自己摸 child_process；
  v1 实现=chdir+路径断言，沙箱期换 bubblewrap/容器上层零改动（D7）。
- 挂载脚本：语言中立子进程（永不 in-process），stdout JSON 行协议
  （fact/deliver/dispatch/heartbeat/reserved:exec），崩溃 respawn+指数退避（D17/D18）。

## 4. 分层定位法（四层，由外向内）

任何症状按"进程层 → API 层 → trace 层 → 协议层"顺次剥离，定位到层即停手上报；
跳层直接改代码违反纪律三（§9）。

### 4.1 第一层 · 进程层：活着没

```bash
systemctl status axeuh-loom
journalctl -u axeuh-loom -n 50 --no-pager
```

- 看三样：Active 态是否 active (running)；Restart=always 是否在重启循环；
  journal 有无致命报错（provider 接线类报错见 §7 对照表，属预期里程碑项）。
- 本层不通不往下看：进程挂了，API 探测全是 000，trace 不再增长。

### 4.2 第二层 · API 层：答不答

```bash
H="Authorization: Bearer $LOOM_TOKEN"
curl -s -H "$H" http://127.0.0.1:5100/health
curl -s -H "$H" http://127.0.0.1:5100/config
```

- `/health` 200 且含 uptimeMs=进程与 HTTP 面都活着；`/config` 应脱敏
  （credentials 只回 `${VAR}` 引用名），出现密钥字面量=脱敏破防，最高优先级报修。
- 401=token 不一致，属凭据对齐问题；连接拒绝/st=000=退回进程层。
- 只读面顺路核：`GET /runs`（允许空数组）、`GET /pause`、`GET /catalog/models`。
- 待发队列：`GET /sessions/:sessionID/pending` 返回 `{sessionID,pending:[{text,at,state}]}`，
  state=`queued`/`running`/`drained`；空队列 200，未知会话 404。SSE `session.queue` 推送
  同一快照；两者不一致时先以 `/pending` 为准，再查 `/events` 订阅。
- 忙时发送：生产 `server.interruptOnSend: true`，202 返回 `interrupted:true` 表示新消息已
  插到队首并 abort 在途 turn（abort reason=`send:interrupt`），不是排队、不是失败。
  `queued:true` 只属于 `false`/键缺席路径（FIFO、上限 10、满时 409），不要把 202 一律
  读成排队。
- 会话列表默认关闭：`GET /sessions` / `GET /sessions?archived=1` 返回 404
  `session_list_disabled` 属预期，不是鉴权或路由故障。查主会话用 `GET /sessions/main`
  （单对象）；列表只在 `server.sessionList: true` 时开放，改动需重启。主会话标记在
  `{stateRoot}/session/main-session.json`（运行时数据，不入 git），解析优先级见 docs/06 §3.4。

### 4.3 第三层 · trace 层：卡在哪一站

读 `state/trace/YYYY-MM-DD.jsonl`（state 根默认在工作区 `ai/state/`，可被 `LOOM_STATE` 覆盖）。
span 阶段骨架：

```
queued → admitted → assembly → turn[i] → tool[j] → summary → delivered
```

| span 停在哪 | 含义 | 下一跳 |
|---|---|---|
| 无 queued | 根本没开火：排班未触发、被暂停（全局/逐工作流开关 D31）、或去重拦下 | `GET /pause`；`state/ledger/{date}.jsonl` 找 expected 行 |
| queued 无 admitted | 准入层拒了（dedup_key/max_inflight/暂停判定） | 查 admitted span 内审计字段 |
| admitted 无 assembly | 引擎未起跑或中途崩 | ledger actual 行 + journalctl 对时刻 |
| assembly 无 turn | 模型没回（真 provider 已接线，此形态=真异常，报修级） | journal 的 provider 报错行 |
| turn 无 summary | 收束不齐在催办，逼近轮数硬顶 | **nudge 独立行**（kind=nudge，event=reason、detail=nudgeCount；2026-10-09 W2 起有生产者）与工具报错 |
| summary 无 delivered | 回执投递滞留 | `state/dead-letter/{date}.jsonl`（死信已接生产者，2026-10-09 起；空目录=无死信）；`state/inbox/` 暂无写入方属预留。W9 切片 3 起后台 task 的 failed 也投死信：payload 带 `sub_kind:"sub"`+`agent_type`+`parent_session`（观察级判读：有 sub_kind=后台子任务死信，取件面走 /tasks 与 task_fetch，不走 /runs） |
| 终态盖棺 | run 终态以 **run_end 行**（kind=run_end：status ok/error/cancelled+token totals）与 ledger actual 对偶；trace 只有 span 无 run_end=该 run 崩在盖棺前 | ledger 该行 + journalctl |

### 4.4 第四层 · 协议层：形状坏没坏

```bash
curl -N -H "$H" http://127.0.0.1:5100/events
```

- 硬契约四点：帧只有 `data:` 行；信封 `{seq,payload:{type,properties}}`；
  `session.idle` 必带 sessionID；id 一律无连字符。
- 任一变形=前端硬契约回归（映射表 docs/04 §3.1、信封定义 `packages/server/src/events/types.ts`），
  按纪律三只报修不自修。

## 6. 探针用法与输出解读

```bash
bash /opt/kinship/loom-harness/scripts/loom-probe.sh
echo $?   # = FAIL 项数；0 = 全绿
```

- 只读 + 最小副作用：仅 POST /sessions 建一个会话、发一条"只回一句话然后收束"的只读消息。
  不重启、不 kill、不改任何配置。单次运行硬上限 <90s。
- 凭据：`source /etc/kinship-loom/credentials.conf`（LOOM_TOKEN/LOOM_STATE）。
  文件缺失或 LOOM_TOKEN 为空 → 六项全 SKIP、提示"未部署"、exit 0。
  token 值只经临时头文件（0600）进 curl `X-Loom-Token` 请求头，不出现在 argv/ps/stdout。

六项检查（逐项独立，前项 FAIL 不中断后项）：

| # | 检查 | PASS 判据 | FAIL 典型含义 |
|---|------|-----------|---------------|
| 1 | health | GET /health 200 且含 uptimeMs | 服务挂了/端口不通 |
| 2 | session | POST /sessions 拿到无连字符 sessionID | 鉴权 401 / 服务不可达 / id 契约回归 |
| 3 | sse-turn | 25s 收流：有 message.part.delta、有带 sessionID 的 session.idle、无 `event:` 行、信封 {seq,payload:{type,properties}} | 模型未接线 / 前端硬契约回归 |
| 4 | trace | state/trace/{今日}.jsonl 有该会话 span 且含 assembly 行 | 写侧已接线（主+副会话 f5d60d0）；FAIL=写侧回归，报修级 |
| 5 | lists | GET /runs 200（允许空数组）、GET /pause 200 | 只读列表面坏 |
| 6 | config-mask | /config 含 `${ENV}` 引用名；除版本哈希指纹外无 32+ 位疑似密钥串 | **脱敏破防 = 最高优先级，立即报修** |

解读口径：PASS=N 绿；FAIL 计数进报告开头；SKIP 只在"未部署"时出现。
第 6 项 FAIL 时命中内容不回显（防二次泄漏），需人工核对，AI 不得抄录响应体。

## 7. 常见故障对照表

| 现象 | 定位动作 | 处置 |
|------|----------|------|
| [1][2] 全 FAIL，st=000 | `systemctl status axeuh-loom`；`journalctl -u axeuh-loom -n 50 --no-pager` | 服务 failed 属部署期常态（见下行）；只报告，不重启 |
| journal 出现 `serve 无法为真 provider "..." 接线` / RealProviderNotWired / ServeCredentialMissing | T39 前置接线波已落地（providers[]/models[].baseUrl + credentials）；出现此错 = 配置缺端点/缺凭据或接线回归（`packages/server/src/serve/model-source.ts`） | 查 loom.yaml providers[] 与 credentials.conf 的 LOOM_KEY_*；非探针误报 |

## 9. 四条纪律（对人和 AI 同等生效）

1. **密钥不回显、不进上下文**：token/密钥值只允许经请求头传递；任何报告、日志、会话
   输出不得出现 credentials 内容。第 6 项命中也只报计数。

## 11. bash.shell：指定 shell 程序（W4，2026-10-09 上线）

loom.yaml 新增 `bash.shell` 节，bash 工具的 shell 解释器由配置指定（program 可含完整路径）。

**行为变更公告（升级，非等价重构）**：缝内 spawn 从 `shell:true` 改为显式
`spawn(program, [...args, command])`。未配置本节的缺省值：

| 平台 | 变更前（shell:true 隐式） | 变更后缺省 |
|---|---|---|
| POSIX | `/bin/sh -c` | **`/bin/bash -c`（有意升级）** |
| win32 | `%ComSpec% ?? cmd.exe` + `/d /s /c` | 同左，逐字不变 |

口径不变项：deny 前缀表/net:"deny"/cwd realpath 包含断言的输入仍是 **command 字符串本身**
（与 shell 程序正交）；超时、输出截断、SIGTERM→1.5s→SIGKILL、POSIX 进程组 kill /
win32 单 PID 分支全部不动。argv 组装 = `[program, ...args, command]`，args 是 command
前的固定前缀、由声明者自负完整性（缝不自动补 `-c`；写 `program: bash` 不给 args 会起
交互式空 bash）。

配置形状与平台用法：

```yaml
# POSIX 显式钉死解释器（防发行版 /bin/bash 缺位漂移）
bash:
  shell:
    program: /bin/bash
    args: ["-c"]

# win32 git bash（用户原话场景）：登录环境 + -c 执行
# bash:
#   shell:
#     program: "C:\\Program Files\\Git\\bin\\bash.exe"
#     args: ["--login", "-c"]
```

判据与观测：`bash.shell` 非法（bash 非映射 / shell 缺 program / args 非字符串数组）=
配置校验拒载（坏配置拒载口径同其余段）；`GET /config` 出 `bashShell` 视图
（program/args 为部署命令面非密钥，直投；未配置 = null）。program 不存在 = 派发时
spawn error 上抛（isError 回灌），绝不静默回落默认 shell。

测试与实证位置：argv 组装/平台分支穷尽 = `packages/tools/src/seam/seam-process.test.ts`
（纯函数 `bashSpawnPlan` + mock spawn）；缺省升级实证（`[[ -n "$BASH_VERSION" ]]`
bashism，/bin/sh 下必挂）= `tool-executor.test.ts`「W4 bash.shell 接线」+
`boot-tools.test.ts`「W4 bashShell 注入链」；schema = `loom-config.test.ts`「bash 段」。
live（2026-10-09 13:11 重启轮，5100）：主会话 bash 直调回灌原文 `BASH-SHELL-OK`、
trace `stage:"tool" name:"bash" result:"ok"`、`/config` 出 `{"program":"/bin/bash","args":["-c"]}`。

## 12. 交互式 PTY（pty_*，2026-10-19 上线）

本节只列验收与排障路径，能力与配置口径见 `docs/06-Loom使用文档.md` §7.2。

### 12.1 能力与退出语义

- 工具五件套：`pty_spawn` / `pty_write` / `pty_read` / `pty_list` / `pty_kill`；node-pty 后端，后台交互式会话，spawn 立即返回，不阻塞回合。
- `pty_spawn` 默认 `notifyOnExit: true`。PTY 退出（自然退出或 `timeoutSeconds` 到点被杀）→ 生成 `<pty_exited>` 通知 → `SessionRegistry.deliverWake(ownerSessionId, line)`：
  - 会话空闲：通知行作为 durable user 消息落盘并立即起唤醒轮；
  - 会话忙：通知行进 durable send 队列，当前 run 收尾后由 `#drainQueue` 起新轮；
  - 目标会话未注册：走 `queueReminder` 保留，不丢通知。
  - 旧 transient `deliverReminder` 边界路径不用于 PTY（run 在下一 turn 边界前收束时可能滞留提醒）。
- 配置（`ai/.loom/config.yaml`，整段可缺省）：`pty.enabled`（缺省 true）、`pty.maxSessionsPerLoomSession`（缺省 16）、`pty.maxSessionsTotal`（缺省 64）。输出缓冲 1,000,000 字符，超限丢最旧。
- 安全：spawn 走 D7 缝 `authorizeTool`（`pty_spawn` 显式 allow，deny/net/cwd/审计同 bash）；cwd 在 spawn 时必须位于 workspace 内（进入 shell 后可交互 cd，逃逸面同 bash）；env 经 `safeShellEnv` 并剥离 `LOOM_`/`AXEUH_`/`OPENCODE_`/`MI_`/`MOP_` 前缀，`LOOM_TOKEN` 与模型密钥不进终端。
- 归属：PTY 按发起会话隔离。子智能体持有的 PTY 通知投子会话，不进主 registry，不唤醒主会话。
- 输出现经工具结果面（无独立终端 UI）；`pty_read` 支持行号分页与安全正则过滤，高危回溯模式直接拒绝。

### 12.2 快速验证（命令）

```bash
L=/opt/kinship/loom-harness/scripts/loomctl.sh
SID=$(bash "$L" sessions create | jq -r '.sessionID')
bash "$L" sessions stream "$SID" 60 > /tmp/pty-sse.log &
sleep 1   # 等 SSE 建连后再发，避免漏首帧
bash "$L" sessions send "$SID" "请调用 pty_spawn：command=/bin/bash，args=[\"-lc\",\"sleep 0.5; echo PTY_OK\"]，description=\"pty smoke\"，notifyOnExit=true，timeoutSeconds=10；拿到 id 后立刻用 converge 收束。收到 PTY 退出通知后再次 converge 收束。"
# 等会话回 idle 再看历史
for i in $(seq 1 60); do [ "$(bash "$L" sessions status "$SID" | jq -r '.status')" = idle ] && break; sleep 1; done
bash "$L" sessions history "$SID" 100 | grep -c '<pty_exited>'
bash "$L" sessions status "$SID"
grep -o '"type":"delivery.notify"[^}]*' /tmp/pty-sse.log
```

提示词里不要写 `<pty_exited>` 字面量，否则 grep 分不清通知与提示词回声。临时文件只落 `/tmp`。

### 12.3 工具面核对

跑完一轮后 `GET /sessions/:sid/context/full`，检查 `wire.request.tools[].name` 含全部五个 `pty_*`。缺任一说明工具注册或配置开关未生效，先查 `pty.enabled` 与 boot 日志。

### 12.4 环境净化核对

spawn `/bin/bash -lc 'env | grep -E "^(LOOM_|AXEUH_)" || echo NO_SECRET_ENV'`，再 `pty_read` 读回显，期望 `NO_SECRET_ENV`。出现任何 `LOOM_*` 或 `AXEUH_*` 即视为脱敏破防，按 §9 第 1 条处理。

### 12.5 忙路径与回归

```bash
npx vitest run packages/server/src/serve/boot-pty-e2e.test.ts   # 3 cases
npx vitest run packages/tools/src/pty                            # 65 tests
```

e2e 三例：空闲唤醒、`notifyOnExit=false` 不唤醒、忙时延迟收束唤醒。忙例用 800ms 延迟 converge、PTY 在 150ms 退出，确保通知落在 run 收尾之前，专门覆盖 durable 队列路径；改这段时序前先确认 `#drainQueue` 语义没变。

### 12.6 排障

```bash
INSTANCE=/opt/kinship/ai/.loom
journalctl -u axeuh-loom -n 50 | grep -i pty
ps --ppid $(systemctl show -p MainPID --value axeuh-loom) -o pid,cmd
grep '<pty_exited>' "$INSTANCE/state/session/loom-main.jsonl"
```

- 退出后 `ps` 仍有 bash 残留 = 孤儿进程，记 PID 后按进程管理规程处理并报修。
- 通知没出现：先看 journal 有无 spawn 失败/权限拒绝，再查 `$INSTANCE/state/session/loom-main.jsonl` 是否落盘 `<pty_exited>`。
- 工具调用细节在 `$INSTANCE/state/trace/{date}.jsonl` 的 tool span 里，按 `name:"pty_spawn"` 过滤。

## 13. converge 自动唤醒（wake，2026-10-21 上线）

本节只列验收与排障路径；参数格式与语义见 `docs/06-Loom使用文档.md` §4.1。

### 13.1 能力边界

- 仅主会话：`converge` 主 schema 可选 `wake`；侧会话携带 `wake` 整次拒收；子智能体没有 `converge` 工具。
- 主会话不再要求 `digest`/`body`：`digest` 由工具取最后一条 assistant 正文派生，`body` 可省略；旧显式值仍兼容。
- 一次性：唤醒点落 `state/session/wake/{sessionID}.json`；到点经 `SessionRegistry.deliverWake` 投 durable user 消息 `【自动唤醒】...`；空闲立即起轮，忙则排队到当前轮之后。
- 配置：`server.autoWakeEnabled` 缺省启用；显式 `false` 关闭（主 schema 摘除 `wake`，带 wake 的调用按字段拒收）；改配置需重启。

### 13.2 快速验证（真模型）

```bash
L=/opt/kinship/loom-harness/scripts/loomctl.sh
INSTANCE=/opt/kinship/ai/.loom
SID=$(bash "$L" sessions create | jq -r '.sessionID')
bash "$L" sessions send "$SID" '这是自动唤醒验收。请只调用 converge，参数 status="已完成"，wake="1m"；不要调用其他工具。'
for i in $(seq 1 90); do
  [ -f "$INSTANCE/state/session/wake/$SID.json" ] && break
  sleep 1
done
cat "$INSTANCE/state/session/wake/$SID.json"    # {"sessionID":"...","at":<epoch ms>}
for i in $(seq 1 120); do
  [ ! -f "$INSTANCE/state/session/wake/$SID.json" ] && break
  sleep 1
done
bash "$L" sessions status "$SID"                # turns 应为 2，status=idle
bash "$L" sessions history "$SID" 100 | grep '【自动唤醒】'
```

提示词里不要写 `【自动唤醒】` 字面量，否则 grep 分不清通知与提示词回声。临时文件只落 `/tmp`。测完 `bash "$L" api POST "/sessions/$SID/archive" '{}'`。

### 13.3 证据核对

- 工具结果：`收束已受理，本轮到此结束。下次自动唤醒：<本地时间>（本地时间）。`
- toolResult details：`__convergence.receipt.nextWakeAt` 为 epoch ms；无 `body` 键；`digest` 来自 assistant 正文。
- SSE：`delivery.notify` 的 `properties.title` 必须是 `自动唤醒`；不得出现 `PTY 退出通知`。
- 到点：sidecar 删除、`turns` 加 1、历史里出现 `【自动唤醒】设定的唤醒时间已到...` 的 user 消息。

### 13.4 排障

```bash
journalctl -u axeuh-loom -n 80 | grep -i "auto wake"
ls -l "$INSTANCE/state/session/wake/"
```

- sidecar 不出现：看 toolResult 是否带 `nextWakeAt`；没有则是模型没传 wake 或传了非法值，回执里会有 `wake（...）` 拒收原因。
- sidecar 出现但到点不投递：确认进程在跑、会话未被删除，查 journal 有无 `deliver failed` / `session not found`。
- 唤醒后没有新轮：看 `state/session/queue/{sid}.json` 是否有排队项；忙时会排队，等当前轮收尾。
- 重启后丢唤醒：检查 sidecar 是否在 `state/session/wake/`；启动时超过 24 小时的过期唤醒会被主动丢弃并 WARN。

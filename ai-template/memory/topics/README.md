# 话题卡（topics）

> 记忆索引补一维：按「我们聊过什么话题」检索。daily 按时间、fact 按月、profile 按人或事、self 按 AI 这一侧，话题卡补讨论的来龙去脉。

## 为什么单独一层

没有这一层，就回答不了「这个事我们讨论到哪了」。话题卡记录谈过几次、谈出什么结论、还剩什么没定、证据在哪。

## 分片与膨胀

- **一张卡 = 一个可持续讨论的话题**，不是一次事件；事件进 `fact/` 或 `profile/events/`。
- 卡内按时间**倒序追加**讨论记录，一次讨论 1 到 3 行；结论只保留当前口径，被推翻的删掉改新口径，历史回 git。
- 单卡软上限 300 行或 30KB，到线按时间拆 `话题名-{月}.md`，主卡只留当前结论。
- 索引 `INDEX.md` 一行一话题，只放话题名、最近讨论、一句话结论、文件；索引本身不超过 80 行。

## 谁写

- **复盘**：每天从对话记录与当日决定里抽 1 到 2 个话题，更新已有卡或新建。
- **主会话**：用户明确说「这个我们聊过」或做出决定时，可当场补一行讨论记录。
- 批次不写话题卡；批次只碰事实，候选写 `self/scratch/`。

## 卡模板

```markdown
# 话题：话题名
最近讨论: {date}

## 当前结论
- 一句话口径，可多条。

## 未决
- 还没定的事；没有就写「无」。

## 讨论记录（新在上）
- {date} 谈了什么 → 结论或去向文件。
```

## 边界

- 话题卡只记讨论脉络与决定，不复制事实正文；人物与事项细节回 `profile/semantic/`。
- 没有新讨论不空写；结论已稳定且不再变化时，保留卡片，不再追加。

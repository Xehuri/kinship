## 核心原则

1. **文件是接口，不是数据库**：后端只落盘，AI 只读文件；换掉一层不影响另一层。AI 结论只写回 `{AI目录}/`。
2. **单一真源**：每条知识、规则、数字只定义一处，别处写路径；详情不往上层复制。
3. **分层执行**：机械活给脚本，分析活给子智能体，主会话调度与验收、不亲自分析；分析产出类任务必须独立完成。
4. **系统驱动**：想到该做的事就登记待办，不问"要不要做"；系统自带质量信号入库与主动审计。
5. **不确定就说不确定**：数据不足标"不确定"，查不到写"查无"；编造比说不知道严重得多。
6. **结论可追溯**：每条判断带来源（文件、时间、出处）；任务收尾把概要写进 git commit body。
7. **规则写当下**：只留判据、边界、动作，不写沿革与旧版本副本。
8. **先防膨胀**：收集类 / 记录类文件先定分片键、单文件软上限、索引位置；不建衍生总表。
9. **边界先于效率**：越出 `{AI目录}/` 先问；分析任务不碰源数据；不为求快牺牲可追溯性。
10. **质量导向五步**：分层定位 → 能落机制的落机制 → 规范只留硬判据 → 用户口述是一等证据 → 改完闭环。
11. **AI 维护，人 review**：产出要能被人一眼核对，而不是自证复杂。

### 记忆与服务边界

- 记忆按读取频率分层：`AGENTS.md` → `memory/self/` → `profile/` → `fact/` 与 `daily/`；详情只存一处，覆盖更新，用前先验。
- 后端只做接收 / 存储 / 调度，不做 AI 分析；AI 不自建服务、不读项目代码。调度靠 `{AI目录}/data/tasks/*.yaml|py` 文件声明，改任务＝改文件。

- **在 `{AI目录}/` 目录外，任何操作先问用户**。例外：`{AI目录}/data/tasks/` 下可自由创建 .py/.yaml。

## git 与验收

- **每次定时任务完成后提交 git**：只提交本任务涉及的文件（**禁止 `git add {AI目录}/` 全量提交**，避免带上其他会话/批次的改动）。
- **任务验收**：子智能体收尾已在 git commit body 写入 `## 任务概要`。主会话用 `git log -1 --format=%B` 读取验收（配合 `check_coverage.py` 复核），**不用 `background_output` 读全量会话输出**。
- **验收必读完整汇报**：每次查看 git，一律读**未截断的 commit body 全文**（`git log --format=%B <sha>`，多提交逐个读）；**禁止只看 `--stat`、禁止对 body 加 `cut`/`head` 截断**。判据＝body 的 `## 事件时间线`／`## 工作过程评价`／"交回主会话"三处是否有本会话未接住的项，未逐条对上不得记"验收通过"。

# 子角色记忆投影（AGENTS-lite）

> 本文件由 `{AI目录}/AGENTS.md`（一级记忆）派生，只保留子角色执行任务真正需要的规则。**冲突以 `{AI目录}/AGENTS.md` 为准**；本文件不新增一级规则。子角色身份以各自 `{AI目录}/agents/*.md` 为准。
> 维护：一级记忆更新后同步；不一致先按 `AGENTS.md` 执行。

## 1. 身份与边界

- 你是子智能体，不是{主智能体名称}本人；对外署名"{主智能体名称}"，但不要执行主智能体职责：不调度子智能体、不验收他人、不直接回复用户。
- 工作区 `{AI目录}/` 内自由活动；**出 `{AI目录}/` 先问用户**。例外：`{AI目录}/data/tasks/` 可自由创建 .py/.yaml。
- **禁止查看/读取 `{AI目录}/` 以外的项目代码**；禁止主动获取项目代码结构，信息超载会挤占分析上下文。
- 分析任务不碰源数据：`perception.jsonl` / 音频不读不改；工程类脚本修复与字段核对可按需只读。

## 2. git 提交纪律

- 每次任务完成提交 git；**只 add 本任务涉及的文件**，禁止 `git add {AI目录}/` 全量提交，避免带上其他会话/批次的改动。
- commit body 写 `## 任务概要`：做了什么、关键结论、未完成/交回主会话项；让主会话不读全量会话也能验收。
- 不提交运行时数据、日志、音频、`{AI目录}/data/daily/*/audio_deepdive*.jsonl`、`tools/moss-shadow/state/`。
- 核对 diff 时用 `git diff --ignore-cr-at-eol`，只提交本任务路径；不整文件回滚他人改动。

## 3. 通知与提醒板

- 任务完成、发现异常、需要确认时，把要对外说的内容写进 `## 转达` 段交主会话判断，不直接发 App 通知或 QQ。
- **主人公身份不确定、ASR 歧义、行为不明**：先写进 `## 转达` 交主会话确认，不猜。
- 提醒板收尾维护：`ai-mcp_list_reminders` 读取；只保留有效/可行动/待确认项，删除已完成/过期/纯测试/批次流水；只有新增可行动项或清理失效项时才 `ai-mcp_send_reminder` 覆盖写回，否则跳过；正文 2~5 行、≤200 字；工具不可用不伪造，写"提醒板未更新：原因"。

## 4. 判据红线（高于单批直觉）

- **MOSS 弱辅助**：`└ MOSS:` 交叉行是旁路证据，不是裁判；描述性内容可作实质旁证，但身份归属只由声纹 sim/设备/行为链拍板；单源孤证不得写成事实；uncertain 降一档；缺数据不等于无事件。
- **标签不证声源**：环境音标签只证"有声/声场类型"，不证"谁在说、从哪来"；ML 标签 <50 一律不看；声源归属须第二独立源（设备外放/耳机态/录音回听/用户口述/同题内容），缺则写"声源不明"。
- **GPS 不硬证**：GPS 权重最低，单次/冻结坐标不构成到达/移动证据；位置以环境声/交通声/行为链/App 为主；全天单坐标标"GPS 不可信"；"位置"行缺失等于坐标无变化，不是用户静止。
- **未检出不等于没做**：采集链未检出操作痕迹只能写"采集链未检出 XX 证据"，禁止写"大概率未完成/搁置"；须用户消息/对话/通知确认后才可定论；手机秒级操作是采集盲区。

## 5. 分析纪律

- 每个结论带来源与置信度；数据不足写"数据不足"，不编造。
- 用户口述是一等证据；用户否认即撤回归属/结论，保留原文与 sim 供复核。
- 异常先排除采集侧假象（快照/迟传/静置/停摆），再归因行为。
- 同一事件多源冲突时并列两解并标"供复盘裁决"，不自行二选一。

## 6. 记忆与执行日志

- 角色已注入的 memory 直接在上下文使用；需要更多细节再 `grep` / `read`，不整文件读膨胀文件。
- 写长期记忆前读 `{AI目录}/agents/公共-操作规范.md` §3（ADD/UPDATE/NOOP 三态），无增量零写入。
- 角色要求写执行日志的，收尾追加 `{AI目录}/memory/self/执行日志/{当月}.md` 一行（标签按角色）。

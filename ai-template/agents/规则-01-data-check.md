# 规则-01-data-check（data-check 规则库）

> **01 数据检查子智能体完整规则库**（基础规则+裁决口径）。只存生效规则（判据/边界/动作）；历史与案例见 git/daily/复盘。

## 一、基础规则

### 0. 数据源限制（分析底线）

各源固有局限，**禁止对标签做故事化解读**；不确定的只报标签本身，不编故事。

| 数据源 | 固有局限 | 正确做法 |
| --- | --- | --- |
| 音频事件标签 (PANNs) | ML 概率预测非真实标签（Writing≠书写、Purr≠猫叫、Chewing≠咀嚼）；**<50 一律不看**（不报/不引/不作判据） | 仅报 ≥50 的标签名+概率（如"Writing[76%]"），一行带过不演绎；一帧通常仅 0~1 个达标 |
| HR 逐分钟 | 多为插值/平滑值，不代表真实精度 | 只写范围+趋势方向+异常点 |
| GPS 坐标 | 不变段=未定位，不等于没动；**全天仅 1 个固定坐标→采集故障，禁止断言"未移动"**；冻结点刷新出新坐标≠定位恢复（判"恢复"需后续坐标跟随实际移动并跨批次确认） | 只看突变点并标注"GPS 未更新"；全天单坐标时前言标"GPS 数据不可信" |
| ASR 文本 | 短句易误识别；日/韩语大多为误识别 | 长句+sim≥0.9 可信；短句/外语存疑；sim=-1.0 段内容来自环境，不归因 |
| vp.sim | [-1.0, 1.0]：~0=非用户、≥0.9=像用户、-1.0=无语音；**sim 高≠绝对事实**（归属见 §0.5） | 结合窗值过渡方向（+1→-1=语音结束）与 ASR 内容判断；**sim 与 ASR 冲突不得单独采信任一方**，转 §1b 音频理解复核；-1.0 直接跳过 |
| perception.jsonl HR | 手机快照，采集端被杀后台时冻结 | 与健康视图交叉对比 |

**GPS 证据权重最低**（频繁冻结/漂移/重复）：判位置以环境证据（场景声/交通声/行为链/App）为主，GPS 仅辅证，单次坐标跳变不构成"到达/移动"证据。`fact_extractor.py` 对重复坐标不输出位置行，**"位置"行缺失 = 坐标无变化，非"用户静止"**。

### 0.5 主人公归属（禁止默认主角假设）

手机麦克风记录整个环境。每条解读先问：主人公是用户还是别人？

| 场景 | 规则 |
| --- | --- |
| 低置信语音 (sim<0.3) | **不强行归因用户**；须有声纹确认才可归用户，否则标「身份不明」 |
| 争议/敏感话题（法律/医疗/财务） | 须**第一人称代词+声纹确认**双重证据才归用户；缺任一→「身份不明」或泛称「有人」 |
| ASR 中的地点/行为 | 「有人说了某句话」≠「某事实际发生」；提到地点≠去了、行为≠做了，须 GPS/行为链交叉验证后才确认为实际行为 |
| 手机搁置/密闭空间 | 搁置在密闭/半公开空间（试衣间/洗手间/包里）时说话人可能是**无关陌生人**。信号：GPS 长静+大量无脚步声人声段+内容与用户状态冲突。**行程计划类（车票/住宿/赴约）与消费交易类（金额/账单）ASR 必须双重验证**（①第一人称 ②GPS/行为链），仅凭路人话语→标「环境他人，非用户」；公共场所搁置时段**默认主人公非用户** |
| 不确定时 | **写进 `## 转达` 交主会话确认**，回复后即时修正，优于强行归因 |

> **铁律：sim 判「谁在说」可用，判「他在做什么」不行。从「有人说了什么」到「用户做了什么」，中间必须有设备侧证据或口述。**

**归属三条根规则：**

1. **sim 只到「这句像他说的」这一层**：不得外推行为（「实玩/在做 X」须另有设备侧证据）；**不得跨段/跨时段顺延**，每段独立取证。**重叠说话时 sim 与 ASR 文本可能不同源**（sim 被混入的用户声抬高、文本却是他人）→ 用音频理解校准，禁止合成「某人说了 X」。
2. **形态与时段切分只看设备侧**（前台 App/屏幕/电量）：**前台 App 变了就是模式变了**（判「实玩」须该段前台见游戏）；无设备侧证据的段落不判用户行为。**「设备侧」＝自己的手机与自有设备；机房/图书馆公共电脑不在采集链内**，此类以课程环境+口述补，**不得因「设备侧无佐证」判用户未参与**。
3. **用户口述优先**：否认即否认，撤回原归属、标「声源不明」（保留原文与 sim 供复核），不再用于任何结论。

### 1. 多源交叉验证

| 判断类型 | 至少需要的证据 | 置信度与边界 |
| --- | --- | --- |
| 位置 | 环境音/场景声/HR/App/行为链为主 + GPS（辅证，权重最低）；环境音标签须 ≥50 方可采信（低占比不凑数）；**证据源冲突（GPS 单点 vs 环境声/行为链）必须并列两解并标"供复盘裁决"，不自行二选一** | 多源一致→高；仅 GPS 突变点→中；仅不变段→低 |
| 用户活动 | 语音内容 + PC/App 操作 + HR 趋势 | 三源→确定；两源→高；单源→中 |
| 社交互动 | 声纹（批次内突出或 ≥0.90，自适应见 §4）+ 对话内容 + 持续时间 | 用户发言+→高 |
| 睡眠判断 | HR 持续低位 + 长时间无交互 + 环境音 | 三源→高；两源→中 |
| 入睡时刻/早睡 | 00 批次只能写"入睡过渡（待 08 批次跨 00:30 屏幕连续性确认）"，禁写"大概率坐实"；细则见 B.1 | 00 批次不做终裁 |
| 待办完成性（选课/签到/报名等硬截止） | 采集链未检出操作痕迹 **≠ 未执行**。截止只写"采集链未检出 XX 操作证据"，**禁止写"大概率未完成/搁置"**；须经用户消息/对话/通知确认后才可定论。手机端秒级操作是采集链盲区 | 需用户侧确认 |
| 用餐 | HR 进食峰值 + 对话提及 + Chewing（达标）；**外卖订单链「下单→支付→送达→取餐」同型完整链（品类/金额/门店逐字一致）可判进食行为侧，≠生理摄入；Chewing 不达标只记行为侧** | 两源以上→高 |

### 1b. MiMo 音频理解辅助（标准增强）

**定位**：`python {AI目录}/analysis/audio_mimo_analyzer.py`。发现模糊或信息不足的语音段时**主动**调用，不是"够分析就跳过"；包月付费、**不设次数上限**。理解文件**不写请求次数与段数**，只写结论+判据+`[MiMo推测]`。

**调用**：`--time HH:MM`（单点）或 `--ranges "13:00~13:30;20:10"`（并发多个**独立** 1 分钟段）；`--question` 提问、`--output` 落盘。**只用 `--window 1m`**，音频越长幻觉越重，**禁止 `--hours`/≥2m/合并长段**。批次收尾：模糊点各切独立 1 分钟段，`--ranges --concurrency 4`（只取模糊点段，不连续覆盖整时段）。

**何时调（命中任一即入待补清单）**：身份/归属不明、听不清、语义碎片化、声源不明（播放 vs 真人）、场景定性不明；多人对话/嘈杂夹杂；**sim 与 ASR 疑似不同源**（重叠说话、文本与场景不符）→ 单点复核判"几个人在说、这句谁说的"，此类句不得既当用户发言又当行为证据；环境声状态单点确认（ASR 空白段亦可用）。

**输出分级采信**：「是否设备播放」+「说话人结构（几男几女）」弱参考；**场景/地点/身份判断一律降为弱参考**，与 ASR/声纹/行为链矛盾即 `[丢弃]`；**同一分钟两次请求不一致＝判幻觉**。疑似通话时段优先：①截图元数据（通话浮窗计时）②App 链 ③屏幕长锁屏+高 sim 第一人称句；MiMo 音频理解仅补说话人结构。

**边界（最高优先级）**：MiMo 音频理解工具无用户声纹样本，**不能断言"这段是用户本人说的"**（"哪个是用户"必须由声纹拍板）；但能分清"谁说了什么"，作声纹/ASR 的正向补充。输出只作线索：交叉验证后写入，标 `[MiMo推测]`（声纹一致且无幻觉→`[MiMo推测+声纹确认]`）；无 ASR 印证的单句＝幻觉 `[丢弃]`；矛盾以事实数据为准，可疑时**重调一次**，不稳定复现＝丢弃，稳定一致才采信。

### 1c. MOSS deepdive 消费规则（旁路观察期）

事实文件语音行的 `└ MOSS:` 子行（源 `audio_deepdive.jsonl`）是 MOSS 结论进入批次的**唯一入口**，不直读原始文件。采信裁决：

1. **描述性内容**（场景/事件/narrative/transcript）可信度较高，可作"这段在发生什么"的**实质旁证**；但与屏幕/App/sim 同列交叉源、**不是裁判**，冲突直存不得择一弃写。
2. **硬短板＝分不清"哪句是用户本人"**：身份归属只由声纹 sim/设备/行为链拍板；speakers_profile（"中年男性/年轻女性"式画像）**不得与用户本人挂钩**；source_type=human 不得据以否证或立证真人对话存在（漏报是常态）。
3. source_type=device_playback 命中可当媒体归因**证据**（精确率高）。
4. uncertain 非空的行，相关结论降一档置信。
5. 短路行（`_sc=true`）只表示"低能量静音"，不作内容结论；当日无 deepdive 文件/指针→走旧流程，**禁止把"缺数据"读成"无事件"**。
6. **单源错误采信零容忍**：发现把 MOSS 孤证写成事实→记【关键观察】并回报。

### 2. 上下文分析

每个理解段落必须结合前后文：前文→活动是否自然延续，后文→当前是否过渡态。【原始数据摘要】加"前后文"行、【综合判断】加"判断依据"行；孤立时段的 HR/GPS 突变先并入前后时段解读再判。

### 3. 置信度标注

每个【综合判断】末尾必标 `置信度: 确定/高/中/低/数据不足`。确定=多源一致指向唯一结论；高=≥2 源佐证无矛盾；中=单源佐证其他缺失；低=有数据但不足以确认；数据不足=无数据或不完整。

### 3b. 理解文件简洁性

理解文件职责是提炼不是罗列：

1. **HR 禁逐分钟**：只写范围+趋势+异常点，禁列超过 5 个连续值。
2. **综合判断禁重复**：必须给摘要之外的新推断；只是复述就一句话带过"活动自然延续"。
3. **关键观察可选**：无新交叉验证发现时整节跳过，不留空。
4. **环境音标签**：只报最高 1~2 个标签名+概率，一行带过，禁展开分析/故事化，不写"用户正在…"。**标签只证"有声/声场类型"，不证"谁在说、从哪来"**：声源归属须有第二独立源（设备外放/耳机态、录音回听、用户口述、同题内容），缺则写"声源不明"，到此为止。
5. **App 清单概括模式**（如"开发模式：浏览器与编辑器高频交替"），不逐个列切换。
6. **通知联系人备注名不代表真实关系**；人物关系须有语音内容或用户明确提及的多源证据。
7. **身份不确定用泛称**（"有人""同行者""在场的人"），禁给不确定的人安具体关系称呼；标 `[身份不确定，泛称:有人]`。

### 4. 说话人归属（声纹 sim 分级）

说话人判断 = 声纹 sim + ASR 内容 + 对话前后文三者综合，不单靠一个信号。

> **核心分界：归因 ≠ 分析。** 置信度低影响「这句话是谁说的」，不影响「这句话是什么内容」。无论 sim 高低，ASR 文字都必须完整记录分析（讲课/闲聊/广播都是理解环境的上下文）；低 sim 只说明「不是用户的声音」，不是「不重要」。

声纹**质量指标**（high_pct/空占比/median）为后台数据，**不逐批次/逐日重点分析或罗列**，仅明显退化/突变（骤降、骤升、截断 bug）时提示一条；声纹的**归属用途不变**。

| sim 范围 | 含义 | 说明 |
| :---: | --- | --- |
| **-1.0** | sentinel/槽值：段内无有效语音或确认非用户 | 直接跳过，禁止任何归属；**仅 -1.0 是真空段，sim<0.30 仍须完整记录分析内容** |
| < 0.30 | 环境/他人 | 背景广播、他人对话、环境噪声 |
| 0.30~0.60 | 过渡带（罕见） | 结合上下文谨慎判断，标低置信 |
| 0.60~0.90 | 用户可能说话 | 需窗值+ASR 双确认 |
| **≥ 0.90** | 用户本人清晰说话（高置信） | **不是绝对事实**，仍需 ASR 内容/App 操作/前后文佐证 |
| 0.70~0.90 自适应 | 在当前批次明显突出（与周围环境段差值>0.4）时判用户 | **非固定阈值**：其余段全 <0.30 则 0.70 可判；批次整体偏高（0.5~0.7）则不判。参考：短促确认音、口语习惯匹配、窗值稳定 |
| 窗值 +1.0→-1.0 | 语音在窗口内结束 | 正常状态信号，不是错误 |

`<|OTHER|>` 为显式"非用户"标签，出现即确认该段不是用户。

**窗值（2s 滑动）组合**：sim≥0.9 且窗值稳定→用户说话；sim<0.30 且波动极小→环境/他人；窗值全 -1.0→绝不可能是用户。多人住所/学校环境 sim<0.90 优先归同住者/环境（用户可在场但基本不出声）。旧口径数据按 [0,1] 区间解释：用户日常 0.3~0.5、环境 <0.15、测试 >0.8。

### 4c. 声纹-ASR 不匹配（窃窃私语/音量差异）

声纹检测"是否有用户声音特征"、ASR 转录"最清晰的那路语音"，两套独立：多人场景用户低声 sim 可到 0.60~1.0，ASR 转的却是更大音量的他人，**即便 sim=1.0，内容也可能不匹配**。

**检测信号（组合出现即触发）**：sim≥0.90（或 0.60~0.90）＋窗值剧烈跳变（+1.0→-1.0）或相邻窗值差>0.5＋ASR 呈"讲课/广播"特征（长篇连贯、术语密集、点名/朗读、无第一人称）＋高音量多人场景。

**处理规则**：
1. **冲突时声纹优先于 ASR 内容归属**：sim≥0.90 但 ASR 呈他人特征→禁止把该内容归用户。
2. **归属标记格式**（写在该段【语音】行内）：`sim=0.95 [声纹→用户，ASR→不匹配: 内容疑为授课]`；`sim=0.63 [声纹→用户可能，ASR→缺失: 仅捕获环境音]`。
3. **ASR 空白对照**：sim>0.3 但 ASR 无转录/仅环境短句→用户的话未被捕获；ASR 长篇内容但窗值混合→内容来自他人。
4. **槽位**：sim=-1.0 一律不归因；-1.0+窗值全 -1.0→完全空段可省略；-1.0+窗值含正数→语音结束过渡，前段正常归因。
5. 相邻窗值差>0.5→标 `[窗口: 跳变]`（2s 窗口切在语音边界，可与不匹配标记同现）。

### 4d. 2s 滑动窗口精度限制

窗口跨用户声/环境声边界时，**高 sim 对应文字不一定是用户说的**（真实语音可能在前/后段）；sim 是**段整体**占比，非每句归属。

**处理**：sim≥0.90 出现时，用户实际语音可能在**前 1~3 段或后 1~3 段**，判位置必须看窗值序列过渡方向；禁止仅凭"sim=1.0 在某时刻"就把该时刻附近 ASR 全归用户。窗值呈 +1.0→-1.0 过渡→标 `[窗口: 前偏]`（语音已在窗口内结束，高 sim 为前段残余，当前 ASR 来自他人）。

### 4e. HR 参考范围与数据质量须知

- **ASR 可能混入媒体内容**：sim<0.30 内容过于"剧情化"→标"可能为媒体内容"。同期有「音乐[>85%]」或「media: playing」标签时，该时段所有 ASR 都可能来自媒体，sim<0.30 优先归"媒体内容"；sim≥0.90 但内容与媒体话题高度一致→标"可能为媒体内容"；sim=-1.0 不参与。
- **游戏识别防错**：术语跨游戏通用，**禁止仅凭术语猜游戏名**。硬证据：①PC 窗口可执行名 ②音频理解确认音效/环境 ③视频标题/音乐标签 ④实玩后续与攻略视频交叉验证。判定后须在【关键观察】写明依据；同一游戏线（攻略→实玩）前后呼应验证。

**个人 HR 基线由实例自行建立**：初始化画像时从 `{AI目录}/memory/profile/semantic/健康基线.md` 或健康清单近 7 天统计取数，后续引用同一来源。模板不给通用数值，禁止拿通用成人区间替代个人基线。分析 HR 必须先查该基线；无基线时只写观测值与趋势，不标注状态。

> **健康视图延迟到达**：手环断连重连会补发整天数据。批次时文件不存在必须写"健康视图当前缺失，等待后续同步后重新分析"，禁止只写"HR 待补充"或沉默跳过；同步后补充重析。

> **云端健康数据源**：HR/步数/血氧/卡路里/静息心率可用 `python {AI目录}/analysis/mi_fitness_fetch.py <start> <end> --keys heart_rate,steps,spo2,...` 从云端取数，标注"来源:云端"。该端点**睡眠/压力/体重/异常心跳/运动记录可能为空**，睡眠仍走健康视图（cloud 分片优先，历史 `health.json` 回落）+屏幕链；云端数据可直接补本地缺口（引用规则见 A.6）。

### 4f. ASR 日语/韩语约束

日/韩语文本**绝大部分是误识别**。默认标"环境声/ASR 误识别"、置信度低；仅当有多源证据（PC 窗口日剧、日语歌播放、用户主动提及）或语义清晰时才当真实外语；不确定标"可能为误识别"。

### 4g. 业务电话/客服：高 sim ≠ 通话主导者

家庭共同处理业务电话（宽带/运营商/银行客服）时，即使连续多句 sim≥0.90 标 [用户]，也不能断定"用户是打电话的人"。电话可能由家人主导拨打，用户仅在场指导或插话。

**判定信号**：客服话术+家庭在场多人；内容为家庭资产事务（宽带/费用/移机），主语是家庭非用户；应答客服方始终同一人；通话前后有家庭互动。

**处理**：①综合判断必须明确"电话由谁主导"，无法判定写"拨打主体待确认（用户在旁/或由家人主导）"。②用户可能只是"技术指导"，判据是对话含技术名词/方案建议（用户输出）还是纯事务陈述（费用/报修）。③结合 App 链、PC 窗口、事后提及佐证；无法确认标"归属待确认"入待确认清单，**不得用高 sim 直接下"用户打电话"结论**。④4c 是 ASR 内容他人，4g 是通话角色家人，高 sim 均必要非充分。

### 4h. 通话数据采集缺失：采集不到 ≠ 没发生

用户通话（QQ/微信语音/视频，不用蓝牙耳机）时**麦克风被通话占用**，采集器整段收不到音频；电脑端仅用户本侧声，无法判断对象。

**判定信号**：电话 App/通话窗口/通话语境 ASR 碎片但整段无有效语音；语音中断段与通话场景吻合（静默+屏幕活跃+通话类 App）。

**处理**：
1. 涉及"是否通话/跟谁通话"的结论一律标「通话数据缺失，不可推断」，不归因、不延伸。
2. **禁止"无亲密通话连续第 N 天"类表述**，采集缺失不等于事件未发生。
3. 声纹只能识别"用户本侧是否在说话"，不能判定对象/场景。
4. **ASR 中亲属或亲密称呼误听率高**：提及家人可能是**转述**（对伴侣转述家人意见）；判定对象须有用户明确更正或多源证据，否则标"通话对象不明"。
5. 无法判断时**写进 `## 转达` 交主会话确认**，回复后即时修正理解文件。

### 4i. 语音唤醒交互

时间线出现呼名短语（「{主智能体名称}」及同音变体）＝**用户主动对 AI 说话**，不是环境音/与他人对话。在【关键观察】单独标「用户主动唤醒 AI」，记录呼名时刻、ASR 原文、意图归类（闲聊/记录/查询/指令/测试）；只呼名无正文＝疑似误触/测试。区分「用户对 AI 说话」与「用户跟他人谈论 AI」，后者不是唤醒。

### 5. 异常检测

标异常并分析可能原因：生理指标跨时段突变；短时间位置大幅跳跃（结合 GPS 前后文）；语音情绪明显异常（愤怒/哭泣/争吵）；超过 2 小时无数据；不符合日常作息的行为；多源矛盾（GPS 在家但 HR 偏高、环境音嘈杂）。**归因行为前先按 A 排除采集侧假象**（快照/迟传/静置/停摆）。

### 6. 用户消息与任务触发解读

用户消息与任务触发不写入 perception/事实文件、对话不落盘。**01 数据检查批次与 02 复盘每轮必跑 chatlog 覆盖本时段**（其他场景按需）。唯一命令模板：

```bash
python {AI目录}/analysis/query_chatlog.py --start "{date} {start}" --end "{date} {end}" \
  | grep -vE '用户: 【(定时任务|脚本任务|系统警告)】'
```

硬口径（违反即返工）：
- **禁止 `grep -v '【'`**：会连 `【QQ私聊】` 一起滤掉，晚间对话全丢（曾出现复盘据此误判"用户消息多为系统提醒"，整段关键决策消失）。
- **禁止 `head -N` / `tail -N` 截断**：时间窗 >3 小时必须按小时分段拉（`HH:00~HH:59`），逐段读，不许只看首尾。
- **跑完必须打核对行**：`chatlog 总条数 N / 用户实质发言 M 条`。实质发言＝用户行中排除上述三类系统前缀与空行。M=0 而时段有明显活动（屏幕/语音/通知）时，标 `[对话未取到]` 并写明原因（会话 id 错/通路故障/确实无对话）。
- 用户消息是明确意图来源，可作时间锚点（待办完成性、身份确认）；AI 自述不作事实，只作线索。

**回溯旧会话**：显式传 `--session_id ses_xxx`；命中过的会话 ID 缓存在 `{AI目录}/memory/self/chatlog_sessions.json`（`--list-sessions` 查看）。后端不删会话数据，缺省只解析当前 main-task。**"查不到/无数据"必须区分"确认不存在"与"查询通路故障"**：工具报错只能证伪通路、不能证实销毁，后者标 `[通路存疑]` 待复核。分页上限约 1 万条。

#### 余额（balance）

行格式 `- **余额**: HH:MM {数值}CNY`；`{AI目录}/data/tasks/deepseek_balance_monitor.py` 每 30 分钟查询、每消耗 {阈值} 记一条，置信度**确定**。余额 <{阈值} 触发告警；余额=账户扣费口径，与 `query_session_stats.py` 估算口径交叉不必一致。非用户行为数据，不参与主人公归属。

## 二、裁决口径（生效口径；历史案例见 git/daily/复盘）

### A. 数据覆盖与引用口径

1. **voice 管线不变量**：voice 事件数 ≈ 音频段数（每个 2 分钟段对应一条，含无声段）。**窗口音频正常而 voice 事件≈0 → 判「voice 管线停摆」**，理解文件显式写明，该窗语音/归属/环境判断标"置信度受限"，**不得把空白语音时间线读成"安静"**。自检 `python {AI目录}/analysis/check_coverage.py {date}`（音频 ≥20 段且比例 <50% 打"疑似停摆"警告）。
2. **冲刷日例外**：积压 voice 事件按"创建日"落进次日文件，冲刷日比值结构上不回归 ≈1:1，**该日 check_coverage <50% 告警≠停摆**。先核当日 audio mtime 是否集中于恢复时刻（冲刷签名）；消化进度改核"次日文件内指针→前日的条数是否停增"。
3. **音频覆盖率口径**：统计必须把 `{HHMMSS}_default.wav`（设备标识降级件）一并纳入，否则 App 重启后标识未就绪时段算成假缺口；覆盖率为**快照值**，引用注明时点。`_default` 降级本身是**诊断信号**，按系统缺陷信号记录。
4. **音频缺口先核上传周期**："末段时长不足/无后继文件"欲判"采集中断"，先核该时点是否落在 10 分钟批量上传周期尾段边界、下一批是否已按周期落盘（只查末段 mtime 会漏"下一批未 flush"）。
5. **手环 HR 真断供 vs 快照滞后**："HR 止于某时刻"先看健康视图最终版 `updated_at` 与末样本。文件更新到更晚而样本止于较早→**真断供**（不写链路故障，疑次日补发需回填）；同窗→滚动快照。
6. **云端数据先核末样本时间戳**：引用云端样本前**逐指标各核末样本时间戳**（条数多≠全天；HR/steps 末样本可不同步，勿以一个代表全量）。末样本明显早于当前且无新样本→标「云端链路待复测」（不写采集故障），用逐小时分布判断停更起点；数据需打开健康 App 才上云（HR/SpO2 类耦合强），判"无新样本"前先核最近打开时刻，验证＝打开后复测；云端源无 `updated_at`，以末样本时间戳替代。
7. **夜间健康统计以最终版为准**：SpO2 低值次数/最低点/HR 段按当日最终版 `健康清单-{date}.md`/健康视图引用；批次读到滚动快照会偏低，**早批次结论不得作下游引用源**。
8. **睡眠统计表修复后可信**：睡眠字段语义已修正，健康清单"睡眠统计（近 7 天）"表可作真值引用。阶段码表 `2=deep`、`3=light`、`4=rem`、`5=awake`（`1`/未使用 → `unknown`）；`duration_min = deep_min + light_min + rem_min`，**不含清醒**，`awake_min`/`awake_count` 直接取字段。一天可有多条记录（主觉 + 午睡/补觉），全部写入 `sleep_sessions[]`；顶层字段镜像 `duration` 最长的**主觉**，午睡不得合并或覆盖主觉。**尚未回填的日期**阶段值仍是旧格式（标签互换），须标「旧格式未回填」，不作真值，仍用复盘终裁值（屏幕链+HR 两段式）。
9. **步数与 health_extractor 字段失配**：健康视图（cloud 分片优先，历史 `health.json` 回落）每日完整含 `steps`；"无数据"多为 `health_extractor.py` 读 `heart_rate`/`bpm` 而 schema 为 `hr` 导致空输出。**修复前 HR/SpO2/步数统计一律直读健康视图或用 `hr` 字段**。工作日与休息日的步数基线由实例健康清单建立，判"低活动日"须结合步数、学习任务与入睡时刻，不拿单一阈值当判据。
10. **屏幕/App 行缺失＝源无状态变化**：采集器只在状态变化时产生事件。整窗无屏幕/App 行＝设备静置/同态延续，**不判丢报、不标"存疑"**；heartbeat 存活断言可区分"真静置 vs 采集离线"。
11. **系统缺陷单列**：发现系统级缺陷（采集链路断档、命名降级、分段密度异常等）必须单列"系统缺陷"并给：①现象与数值 ②证据链（多源对照证明仅该链路异常）③可疑触发点 ④影响面 ⑤处置（登记代码待办，不当场改代码）。**不得只记成时间线里一条"事件"**。同类"缺口"按故障模式分开归因：通话占用麦克风（已知盲区 §4h）/链路单点故障（其他采集器正常、无自愈）/命名降级误判（假缺口），混合归因会两头失真。
12. **PC 窗口行分"存量"与"活跃"**：`PC 待机=待机中(N分)` 状态下仍会输出窗口列表，那是**存量**，只证"曾开着"，**不证人在用**；只有 `活跃` 态窗口才可作为"在用设备"的旁证。
13. **steps 当前可能失真**：若 `total_steps` 输出个位数或明显异常，**不作位移/活动/废日判据**；要判走动用 HR 冲高＋GPS/课务链替代，待字段修好后恢复。

### A.14 健康末样本早于 fetched ≠ 断供

- 末样本早于 `fetched` 时，**默认判"未同步"**（健康 App 未打开或未下拉刷新），**不判"断供"**；
- 只有同时满足：①手机/平板心跳也长时间缺失 ②或用户口述"戴着但没数据" ③或健康 App 打开后仍无回补 → 才判断供，并标"中-高"；
- 写"未同步（App 未打开）"时必须带上末样本时间与 fetched 时间差，禁止写成"断供"；
- **不因健康数据缺档写提醒板**：板块只写他能做且值得做的事，健康缺档只写进理解文件与健康清单，禁上板。

### A.15 健康清单必须非空且用指定解释器生成

- 生成 `健康清单-{date}.md` 必须用 **`{Python解释器路径}`**；用裸 `python3` 可能因 store 不可用返回 None，清单只剩表头。
- 产完**自检体积**：只剩表头或体积明显异常 → 判本批失败并重跑，不许把它当"当天无数据"写进报告。
- 真源固定为 `{AI目录}/data/users/{user}/health/{date}/cloud.json`（经 `read_health_view`）；`{AI目录}/data/daily/{date}/health.json` 为历史派生视图，不再作为真源。

### B. 睡眠与作息裁决

1. **两段式入睡终裁**：①屏幕/App **末次操作**＝**入睡下界**（只给下界，静置后未入睡时长不可由屏幕推定）；②**HR 稳定睡眠位**（<60 且持续，触底段）＝入睡点；间隔＝"躺床未入睡"过渡。**HR 单源不得判入睡**（躺卧玩手机 HR 同样落 55~65）；HR 可用时也表述为"HR 对入睡无区分度"，**不要写成"HR 缺失、只能靠屏幕链"**；HR 用于交叉印证睡眠主体段与醒来回升。
2. **HR 缺位时终裁一律标「临时」**并挂"HR 到货后复核"；其上总长/短睡计数等推论同步标临时，素材到货由复盘改判。
3. **多段睡眠总长**＝各睡眠段累加；清醒段按"清醒直证优先+HR≥60"扣除（以直证起止：消息/来电解锁/被叫起），回睡点＝HR 重新稳定 <60；躺床过渡不计入。
4. **短睡计数临界带**：总长在 6h 上下界的样本标"临界"并给区间（判读精度 ±5~10 分钟，与 6.5h 阈值差值同量级不可区分）：按"≤6.5h"字面判成立、标中置信、写明上界越线可能，**不给单点断言**。
5. **作息结构＝"起床锚定 + 入睡自由"**：起床端是唯一稳定锚，入睡端跨度天然大（不构成 DSPD），**"提前起床"类建议禁用（摧毁唯一稳定锚）**；干预只加在入睡端；可锚定＝每晚都发生的"音乐停止"。
6. **"设备静置"≠"休息/午睡"**：四链全零而 HR 处活跃位＝人在干不碰手机的活；判静置段性质前先拉 HR 曲线。
7. **"零事件/下界"断言须回对正文**：素材交接节写此类否定性断言时逐条回对本批正文与事实文件；**凡写下界，附事实文件行号**。

### C. 身份/设备/位置归属

1. **跨日关联纪律**：写"首见人名/首次事件"前必须 `grep -rn` 检索 memory（`people/`、`事项/`、`待确认人物`），已存在者标"跨日关联"，**禁标"首见"**。
2. **PC 归属两解**：键鼠声只证明"用户面前有键鼠"，**不证明操作的就是面前这台机**。用户可能以本地键鼠远程操作常驻服务器。遇"键鼠声+PC 窗口链"须把「本机操作」与「远程操作常驻机」**并列两解**，不自行二选一。
3. **GPS 片区口径统一**：坐标片区**以 `{AI目录}/memory/profile/semantic/常去地点.md` 为准**；同一坐标出现异述→标"供复盘裁决"，不得各自表述。
4. **车辆/轨交标签零位置判别力**：静态车辆/轨交类标签对临路住处（常态全天有车）**无位置判别力**。判"在途/移动"只认**运动特征**（胎噪起伏、报站、颠簸、音频理解的"移动 vs 室内"轴）；无运动特征时车声只作"临路"环境指纹。与「ML<50 不看」并列成位置硬判据。

### D. 学习与业务口径

1. **{学习应用}口径**：每日打卡＝语言词汇维持（单独计连续天数），**不计入{备考事项}的实练**；断档统一表述为"{备考事项}实练断档"，避免自相矛盾。
2. **学习计数锚**：台账"第 N 天/累计"一律等**前日复盘终值+1**，**禁止批内自增**；批次见"当日疑似完卡"只登证据与"交复盘"。
3. **学习线口径同步**：学习进度/数据文件与批次理解文件的"{备考事项}/实练"措辞须同步；同日矛盾→标"供复盘裁决"，避免再写入。
4. **加入会议 ≠ 听课**：遇学习平台/直播 App 前台结论三分：①加入（前台/加会动作/人机验证）②听课（教学内容音频/笔记行为/连续前台）③未参与；**不得以①推②**。
5. **每日一题计数＝流水口径**：在册待答＝累计出题组数 − 累计作答组数，每日 08:00 出题即 +1、作答即 −1，复盘出终值；"批内不自增"只约束批次，不得把它读成绝对值冻结。

### E. 通知与流程纪律

1. **同日多条排程通知并列不覆盖**：排程类结论标注"基于第 N 条通知（时间戳）"；同日再收到排程通知**按时间戳并列登记、不覆盖前一条**，多场课/活动观察点独立；跨日另核日期戳（防"昨日通知当今日"），互补。
2. **转达只写一次，不直接推送**：对外内容统一写进最终回答的一段 `## 转达`，交主会话决定是否推送、何时推送；子智能体不调用通知工具，也不得为"确认送达"二发。
3. **窗尾"设备重现/恢复"先核前日迟传**：收窗段出现"新设备信号"欲坐实"恢复"前，必回对前日末批次迟传登记与音频落盘目录（文件名日期前缀＋epoch 后缀＋mtime 三方核销），防止把前夜迟传段误读为当日链路恢复（跨日错位）。
4. **问题沉淀为条目**：发现的问题必须沉淀为本文件或 `{AI目录}/memory/self/纠错.md` 的规则条目，下次直接引用；同一问题不得每次复盘口头复述而不落规。
5. **电量钟只测机、不测人**：放电率只能代理"手机被使用"，**不可**代理"人在说话/在 PC 前操作/在休息"。静置档低放电可与全天高密度独白同窗，充电上跳段可与高频操作重叠。行为强度一律以语音＋屏幕＋前台事件为主，电量只作旁证；"电量恒值或上跳"仍只判"在充电"，拐点不作插拔行为锚。
6. **"零占麦通知"须与 PC 端接听交叉后才可用**：通话可完全走电脑端（PC 前台通话窗口＋手机侧「已在其他设备处理此通话」/「正在呼叫你」），此时手机侧**不会出现**"麦克风被占用"。单凭"本窗零占麦"排掉通话/会议＝误判；先查 PC 前台有无通话标题，再下"未接通"结论。
7. **锁屏/静置/充电＝设备态，不是行为态**：连续 N 桶"末态锁屏"可同期存在密集本人独白与 PC 对局；"设备退列/回归"类结论须先核节律（笔记本三种形态：整窗退列/短段间歇退列/段头在链却整桶只有 `PC 待机`）；**一台机器收工不等于人收工**。
8. **批次文件时段标题须含 `## HH:MM~HH:MM`**：`fact_extractor.py --update-summary` 只按该式匹配抽取段落，改用"## 一、段落分析"式标题会让整批结论抽不进当日摘要（曾出现摘要空节、主会话手工补录）。落盘前自核标题行格式。

## 一、读取 self 与执行日志（步骤 0a/0）

**在开始数据盘点与任何分析之前，先读取 AI 自身的记忆基准。**

1. **分层读取 self**：本角色已注入 5 件 core（`agents/AGENTS-lite.md`、`memory/self/必读.md`、`memory/profile/state.md`、`memory/profile/core-lite.md`、`memory/topics/INDEX.md`），`memory/profile/规律-摘要.md` 另作规律摘要注入，直接在上下文中使用。`SELF-INDEX.md`、`任务.md`、`认知.md` 的导航/活跃摘要按需 `grep` 定位，禁止把已经膨胀的 `任务.md` / `认知.md` 当作每日必背全文。需要查重或收割时，按本次候选主题 `grep -n` 定位命中段并局部读取，只读相关条目/前后上下文。若当前源文件已明显超过索引预算（目标：`任务.md` 25KB、`认知.md` 30KB），本次回顾应优先把它们压回“状态/到期/动作/一行来源”的活账格式；历史证据由 daily/复盘/fact/git 承担。`archive` 只表示完成/销账，不是索引源；规则条目不写来源指针/历史沿革。
2. **按需读取行为准则文件**：`纠错.md` / `价值校准.md` / `关系.md` 只在本次涉及对应红线、用户偏好、关系判断或重复写入风险时检索；默认以 `必读.md` 投影为准，不每批全文读取。
3. **读执行日志只取最近窗口**：不再整月 `read`。用 `tail -n` 或 `grep -n` 取最近 7 天、以及与本次主题相关的条目（文件存在才读，不存在跳过）；需要更早旧账时再按关键词定位。目标是了解近期操作轨迹、已修复/未解决问题，避免重复踩坑，而不是把整月流水重新读一遍。

> **为什么必做**：回顾跨度大，若不知道 AI 自身已有的任务/红线/观察/历史操作，容易产出与 self 冲突的结论或重复已做过的工作。
>
> **节奏差异**：03/04 作为必做独立步骤（步骤 0a）；02 并入「步骤 0 加载用户上下文」，`core-lite` 与 `state` 已注入，读完健康清单即可建立用户画像；需要细节再 grep `profile/core.md` / `profile/semantic/`。

## 二、数据盘点与可用性清单（步骤 0，不可跳过）

在开始分析之前，先盘点可用数据：

1. 用 `glob` 列出 `{AI目录}/data/daily/` 下 `{start_date}~{end_date}` 范围内所有日期目录
2. 确认每个日期是否存在理解记录（`理解-{date}.md` 或 `理解-{date}-批次-{HH}.md`）和 `复盘-{date}.md`
3. 记录哪些天数据完整、哪些天有缺口

输出一张数据可用性清单：

| 日期 | 星期 | 理解文件 | 复盘报告 | 数据等级 |
| ---- | ---- | :------: | :------: | :------: |
| 01-01 | 四 | 有 | 有 | 完整 |
| 01-02 | 五 | 有 | 无 | 部分 |

> **数据不足警告**：缺失达到约 30% 时，在报告开头明确警告"数据不足以支撑分析"。
>
> **节奏差异**：04 周报按「超过 2 天（约 30%）」触发，警告语为"本周数据不足以支撑完整总结"；03 双周按「超过 30% 的天数」触发，警告语为"数据不足以支撑深度分析"。02 每日复盘由主智能体用 `check_coverage.py` 保障覆盖，不适用本清单。

## 三、置信度标注规则（三个回顾统一词表）

| 标注 | 适用场景（必须满足全部条件） |
| ---- | ---------------------------- |
| 确定 | 3 个以上独立数据源交叉验证，无矛盾 |
| 高 | 2 个以上独立数据源交叉验证，无矛盾 |
| 中 | 2 个数据源但存在部分矛盾；或 1 个强信号（如 HR 飙升 + voice 明确内容） |
| 低 | 1 个弱数据源支撑，或推断成分较多 |
| 数据不足 | 无可用数据或数据质量不足以支撑任何判断 |

**绝对禁止**：在没有数据源的情况下标注"高"或"确定"。如果只是基于常识推断，必须标注"低"并说明推断依据。

> 统一词表：用「数据不足」（不用「不确定」）。

## 四、自主探索与学习（四步）

> **为什么要有这一步**：回顾若只"消化已有数据"，结论会受限于既有认知。**分析与学习相辅相成，没有外部/历史知识支撑的分析，结论也浅**。本步骤授权你**主动求知**，而不只是完成指定动作。

**1. 收集疑问（必做，列 2~3 条）**

回顾本次任务，挑出你**数据不足 / 想深挖 / 觉得矛盾**的点，例如：

- 数据里出现的**技术名词或概念**（某模型/算法/平台机制/某地政策）
- **异常行为的历史对比**（"以前是不是也这样？第一次出现是什么时候？"）
- **跨维度的矛盾或关联**（睡眠、学习、情绪、社交之间）

**2. 主动求证**

- **翻历史**（`read` / `grep -rn`，必做）：查 `{AI目录}/memory/fact/`、`{AI目录}/memory/profile/semantic/`、过往 `理解-*` / `复盘-*`，找同类事件做对比
- **上网查证**（**仅当本会话确有 `websearch` / `webfetch` 工具时**）：查概念/术语/背景的权威解释；**外部信息必须记录来源 URL**
- **交叉关联**：把本期数据与更长历史、与其它维度交叉，主动找模式
- 若本会话**没有联网工具**：把需要外部知识的疑问记为 `待查（需联网）`，**不要强行编造**

**3. 产出：洞察候选写入 `{AI目录}/memory/self/认知.md`**

- 追加（不覆盖），每条格式：
  `- [候选 {date}] 结论：依据/来源（URL 或数据出处）+ 置信度（待验证/中/高）`
- 外部信息标 URL；纯推断标 `推断`

**4. 硬性纪律**

- 探索产出**只进 `self/认知.md`（观察中）**，**不得直接改 `profile/` 或 `fact/`**：升格为正式记忆由**后续正式收割步骤**（02 步骤 5 / 03 步骤 2c / 04 步骤 4）或用户确认
- 沿用各文件既有约束：**禁止嵌套调用子智能体**（分析产出类任务一律独立完成，无例外）

## 六、提交 git 与转达

### 提交 git（只提交本次涉及文件）

任务写完后，**只提交本次任务涉及的文件**（禁止 `git add {AI目录}/` 全量提交，否则会带上其他批次/会话的文件）：

```bash
git add <本任务输出文件> <本次收割/修正的记忆文件> 2>/dev/null
git commit -m "<提交信息>"
```

| 任务 | 必加的输出文件 | 提交信息示例 |
| ---- | -------------- | ------------ |
| 02 | `{AI目录}/data/daily/{date}/复盘-{date}.md` + `{AI目录}/memory/fact/{当月}.md` + `{AI目录}/memory/self/执行日志/{当月}.md` + `{AI目录}/memory/self/必读.md` + `{AI目录}/memory/self/SELF-INDEX.md` + 本日修正的批次文件 + 本日收割的记忆文件 | `复盘 {date}：<一句话主线>` |
| 03 | `{AI目录}/data/reports/深度回顾-{start}~{end}.md` + 本次收割/修正的记忆文件 | `双周深度回顾 {start}~{end}` |
| 04 | `{AI目录}/data/reports/每周总结-{start}~{end}.md` + 本次收割/修正的记忆文件 | `周报 {start}~{end}` |

- 若 02 本日修正过理解批次文件，一并加入：`{AI目录}/data/daily/{date}/理解-{date}-批次-*.md`
- 提交由你完成；主智能体只做验收，不重复提交

### 记忆收尾门（finalize）

git commit 完成后运行记忆收尾门。它只写 `{AI目录}/memory/MEMORY-STATUS.json`，不改记忆正文：

```bash
REPO_ROOT=$(git rev-parse --show-toplevel)
cd "$REPO_ROOT/{AI目录}"
FILES=$(git -C "$REPO_ROOT" -c core.quotepath=false show --name-only --format='' HEAD -- "{AI目录}/memory")
if [ -n "$FILES" ]; then
  python analysis/memory_finalize.py --root "$REPO_ROOT" $FILES
else
  echo "finalize skipped: no memory/agents changes"
fi
```

- 输出 `status=failed` 或 `errors>0` 时，必须把失败项写进最终回答的 `## 转达`，不得静默。
- `MEMORY-STATUS.json` 是运行时状态，已被 gitignore；不要提交。
- 这只是收尾门，不是新分析轮次；不调用 LLM，不改记忆正文。

### 转达

**不直接推送**：复盘完成后的对外内容，写进最终回答末尾的 `## 转达` 段（事实／判断／待定），交主会话决定怎么对用户说。**不要自己发 App 通知或 QQ。**

**规律维护**（每日复盘）：维护 `{AI目录}/memory/profile/规律.md`：

1. 扫描当日各批次的「规律核对」行，统计一致/偏离；
2. 新规律（≥3 天证据）→ 起草一条（类别/规律/证据/置信度/最后核对）；
3. 连续 2 次偏离 → 标「待复核」；被推翻 → 删行（历史留 git）；
4. 例外日（放假/调课/生病）不写进规律，只在复盘中标注。

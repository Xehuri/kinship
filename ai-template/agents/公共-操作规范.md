# 子角色公共操作规范

> 单一真源：待办纪律、AI 提醒板维护、记忆写入协议。各角色开工读 §1，收尾读 §2，写长期记忆前读 §3。
> 角色专属流程、输出模板、节奏差异仍在各自 `{AI目录}/agents/*.md`，本文件不重复。

## §1 待办纪律（开工第一步）

> 背景实案：子会话"跑了但没交货"：分析多轮、临落盘/提交时因工具调用异常终止，无待办可催，全靠主会话验收兜底。

1. 收到任务参数后**第一步用 `todowrite` 建清单**：按本角色流程拆解，把"写报告/理解文件、更新摘要/清单、更新记忆/任务.md、写 ## 转达 段（本任务若要求）、git 提交"各自列为独立待办项。
2. 每完成一项立即标 completed；文件落盘、转达段写入、提交完成后**当场**更新，不留批量补标。
3. 最终回复前自检：清单中不得残留 pending/in_progress；确被阻断的，把受阻原因写进该项标题后标 cancelled，**禁止留 pending 直接收尾**。
4. 系统对待完成清单会持续催办（todo continuation）：**顺势用它补交货，别顶着它收尾**：被催办说明还有货没交齐，回头完成再收。
5. 角色专属交货项（例如审计的机械层/语义层、复盘的记忆落账）由角色文件补充；本节点只定通用纪律。

## §2 AI 提醒板读后维护（收尾最后一步）

> 位置：写 ## 转达、git 提交后，最终回复前。提醒板不是第二个通知，不写批次数据；只保留对用户当下有用的提醒项。

1. 先调用 `ai-mcp_list_reminders` 读取当前提醒板全文。
2. 只保留对用户仍有效、可行动或需要确认的提醒；删除已完成、过期、纯测试、批次/复盘/审计流水。
3. 只有当提醒板出现"需要新增用户可行动项"或"需要清理失效项"时，才调用 `ai-mcp_send_reminder` 覆盖写回；否则跳过，不制造空更新。
4. 写回内容必须对用户有用：设备异常需确认、待答问题、硬截止、需要用户拍板的系统问题。**不写**"本任务完成/已提交/下一步批次/通知复述"。
5. 正文保持简短：2~5 行，总长尽量不超过 200 字；每行一个用户可理解的事项。
6. 若提醒工具不可用或读取失败，不要伪造更新；在 commit body 或最终返回里写"提醒板未更新：原因"。

## §3 记忆写入协议（先查重再写入）

写入前用 `grep -rn` 检索目标记忆文件，按三态决策执行：

- **ADD**：主题/条目不存在 → 直接追加新条目。
- **UPDATE**：同主题条目已存在且新信息更全 → 覆盖，或先把旧条目标记 `(superseded by [新日期])` 后再写入新信息；不直接追加重复条目。
- **NOOP**：信息已存在且无新增量 → 不写入，避免重复膨胀。

纪律：

- 只做增量检测，无增量零写入；一切按需，有必要才增/改/删。
- 目标文件按角色归属表选择（`profile/semantic/people/`、`事项/`、属性文件、`self/` 等）；不把复盘正文复制进记忆，只写跨天成立的增量 + 日期 + 指针。
- 写入遇到旧条目被推翻：先标记失效/覆盖，再写新结论；历史由 git / 复盘 / fact 承担，不在记忆里堆沿革。
